## 选择与编写用例

选能发现实际回归的最轻路径，已有用例覆盖时复用或扩展。修复先确认失败能重现，纯重构检查原有行为，新增能力需要自己的参考和用例；不为可逆的低影响文字或格式调整编写样板测试。

断言可观察行为及必要协议顺序，不机械固定内部调用次数、标签和布局；只有它们本身是必须保持的行为时才固定。替身用于隔离外部条件，CPU mock 不证明设备数值或通信完成。数值阈值来自数学与参考，不为通过测试而放宽。

## 新组件和跨层变化

新组件先定义其数学与资源合同，寻找可复用的测试 helper 和参考组织。相邻组件测试只能证明共享机制的一部分，不能代替新组件自己的前向、训练及设备验证。

新增设备测试沿用测试指南规定的 launcher 与 worker 分工。实际入口不存在时标为拟新增；不能把计划中的测试写成已运行。公开行为变化补相关用例和文档。

只改变队列顺序时验证任务覆盖与合法依赖；改变 task 粒度或数量时，还需验证事件计数、完整工作量和完成协议。缓存回归按[同一缓存内的变化范围](../rules/architecture.md#配置和计划缓存)选择用例。

## 执行边界

- 明确指定 `tests/ut` 或 `tests/torch`，避免无参数 pytest 混收 CPU 与 NPU。
- `tests/ut/build/check_build.py` 是独立入口，普通 pytest UT 不执行它；其调用条件见[构建检查规范](../../tests/ut/build/README.md#调用时机)。
- 已注册的 NPU 测试通过现有 launcher 执行，复用设备锁、超时和 Root/资源清理，不绕过 launcher 直接启动 worker。指南明确提供的独立回放按其入口执行，另行核对设备占用、超时及退出清理；回放结果只证明实际覆盖的场景。
- 安装态验证在源码外运行，核对实际导入位置与 payload；环境准备和制品身份见[构建指南](../../docs/build.md#安装与验证)。设备对象按目标架构构建，依赖与 patch 可复现；build 和临时诊断制品不提交到源码仓库。
- 修改检查或新增测试时核对真实收集、CI job 选择及失败传播。已注册 hook、CI 实际执行与合并必需检查分别取证。

## 证据与结论

交付时给出实际检查命令、结果和未验证部分，不要求局部修改填写完整证据表。涉及构建、迁移、设备或性能时，再记录足以复现的源码/依赖 revision、配置、制品身份和日志位置；设备测试核对相关 worker/rank 是否完整执行。

CPU、ABI、native 构建、NPU 数值/生命周期和性能各自报告。collect 只证明收集；skip、缺失结果或超时不证明通过；计时 smoke 不等于发布性能门槛。

性能对照使用相同输入、数值、完整工作量和计时条件，关闭打点并保留波动。输入、源码或制品变化后判断旧证据是否仍覆盖本次路径。仅运行无关测试不能支持修改正确；缺少设备或环境条件时，继续可独立完成的工作，明确剩余验证。
