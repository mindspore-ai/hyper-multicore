# 构建检查规范

本目录存放依赖完整源码 checkout 的轻量构建检查，用于保护构建辅助逻辑的正确性和文件操作安全。
检查入口为 `check_build.py`，使用标准库 `unittest` 和已有构建依赖，可独立运行，不需要 pytest、Torch/PTA 或 NPU。
安装态 UT 不自动收集本目录；运行时适配选择、资源完整性和初始化状态由
[加载用例](../test_native_loading.py)看护，算子功能和数值验证归属对应组件测试。

## 看护边界

本目录接收可能导致依赖选择错误、旧产物被错误复用、制品不完整或非受管数据被删除的构建逻辑回归。
用例按可观察结果组织，覆盖关键成功路径和有明确后果的失败路径，不按内部模块或函数逐项铺设测试。

检查使用真实构建辅助函数处理小型合成数据。下载、安装、编译和设备操作由必要替身隔离，
不用于证明真实工具链、外部框架或设备 kernel 的兼容性。需要这些资源的验证归属独立的构建或设备验收。

## 编写与扩展

- 在 `check_build.py` 的 `BuildChecks` 中增加以 `test_` 开头的方法，名称说明被保护的结果。
- 先确认现有用例是否已覆盖该契约；同一故障保留主要调用链上的代表场景，避免重复模拟多个层级。
- 复用文件内的临时目录和清理机制。环境变量、模块替身和文件状态在用例结束后恢复，不依赖执行顺序。
- 所有文件操作限定在临时目录中，不读写开发者的 venv、下载缓存、项目构建缓存或正式产物。
- 断言面向依赖请求、校验结果、发布状态及受保护数据，不固定源码字符串、函数布局、日志措辞或内部计时字段。
- 夹具保留在本文件内，不从其他测试文件导入；仅在多个用例需要相同准备逻辑时共享辅助函数。

新增或修改用例后独立执行该入口，并核对总耗时及临时资源清理。用例数量随实际看护需求变化，
不以增加数量或展开路径、平台、异常组合为目标。

## 调用时机

修改依赖准备、缓存复用、目录管理、制品校验或发布收尾逻辑时执行构建检查。
检查可从仓库根目录或 `tests/` 直接运行：

```bash
# 仓库根目录。
python tests/ut/build/check_build.py

# tests/ 目录。
python ut/build/check_build.py
```

[构建入口](../../../docs/build.md)通过 `--tests on/off` 控制自动执行，显式设置覆盖模式默认值：

| 构建模式 | 默认行为 | 显式设置 |
| --- | --- | --- |
| 默认开发构建 | 不执行构建检查 | `--tests on` 开启 |
| `--all` | 执行构建检查 | `--tests off` 关闭 |

自动检查在获得构建锁、初始化日志及输出事务后执行，先于环境准备和 native 编译，每次构建执行一次。
检查失败会停止构建并沿用提交前失败清理规则。关闭检查不取消实际编译、加载或制品完整性校验。

## 耗时控制

整个检查入口保持秒级耗时。新增用例时对比入口的总耗时，检查是否引入了不必要的准备和重复工作。
夹具使用小型文件和最小数据集，不扫描真实安装目录，不创建真实框架环境，不进行网络访问或编译。
不加入性能测试、长时间等待或大规模并发场景；需要这些条件的回归在独立验收中执行。
检查入口不增加额外安装依赖或专用调度、缓存、超时框架。
